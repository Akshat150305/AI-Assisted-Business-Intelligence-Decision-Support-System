## Principles

1. Nothing is silently deleted or changed. Every action is in `data/processed/cleaning_audit_log.csv`.
2. Removed rows are kept in `data/processed/rejected_rows.csv` with the reasons.
3. A value is only repaired when it can be derived from other data. Otherwise the row is quarantined.
4. Duplicates: the first occurrence is kept. The first copy is assumed correct, which should be confirmed with the data source in a real project.

## Limits of this summary

- The pipeline can only detect problems that break a rule. A wrong value that still looks valid (for example a plausible but incorrect quantity) would pass undetected.
- Quarantining rows removes their revenue from the analysis. In a real project the size of the rejected revenue would be reported to the data owner.
